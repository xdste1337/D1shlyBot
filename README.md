# Dishly — Telegram-бот с идеями для готовки

Dishly ищет рецепты только в локальном каталоге. Запросы разбираются локально по словарям и фильтрам; внешние API и платные сервисы не используются.

В каталоге 175 демонстрационных рецептов, включая выпечку и 25 рецептов в общей категории «Полезное / ПП». Карточки показывают ориентировочную калорийность на порцию, рассчитанную по ингредиентам. Рецепты служат примером формата и не являются профессионально проверенными; проверяйте готовность продуктов и корректность количества под свои условия. Фото в карточках — иллюстрации, а не гарантированно точное изображение готового блюда. Подпись указывает автора, лицензию и страницу источника; при недоступности фото карточка рецепта всё равно открывается.

В разделе «Ещё» можно собрать персональный план на 3 дня и общий список покупок с суммарными количествами. Dishly учитывает аллергии, исключённые продукты, доступную технику и число порций; рецепты открываются в сообщении плана.

## Запуск на Windows

1. Установите Python 3.11 или новее с python.org. При установке включите добавление Python в PATH.
2. Откройте PowerShell в папке проекта.
3. Создайте виртуальное окружение и установите библиотеки:

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install -r requirements.txt
   ```

4. В Telegram откройте [@BotFather](https://t.me/BotFather), выполните `/newbot`, задайте имя и username, заканчивающийся на `bot`, и скопируйте токен.
5. Создайте локальный файл настроек из шаблона и впишите токен:

   ```powershell
   Copy-Item .env.example .env
   notepad .env
   ```

   Замените значение `BOT_TOKEN`. Чтобы получать сообщения пользователей о проблемах и вопросах по оплате, укажите свой Telegram ID в `ADMIN_TELEGRAM_ID`; его покажет команда `/id` в боте. Для Dishly Plus задаются `DEEPSEEK_API_KEY` и выбранная цена `PLUS_MONTHLY_STARS`. Не отправляйте ключи в чат и не добавляйте `.env` в git. Файл уже исключён через `.gitignore`.

6. Запустите бота:

   ```powershell
   python -m dishly.bot
   ```

Оставьте это окно открытым: локальный бот работает, пока запущен процесс и компьютер подключён к интернету. Откройте своего бота в Telegram и нажмите **Start**. SQLite-файл `dishly.sqlite3` создаётся автоматически в корне проекта. Токен можно отозвать через BotFather командой `/revoke`.

## Запуск на Linux-сервере

1. Установите Python 3 и модуль виртуальных окружений, затем в корне проекта выполните:

   ```bash
   python3 -m venv .venv
   . .venv/bin/activate
   python -m pip install -r requirements.txt
   ```

2. Создайте `.env` из `.env.example`, укажите `BOT_TOKEN` и `ADMIN_TELEGRAM_ID`. Узнать ID можно командой `/id` в боте. Администратор должен хотя бы раз открыть бота и нажать Start, чтобы бот мог присылать отчёты и вопросы по оплате.
3. Если серверу нужен прокси для Telegram Bot API, укажите в `.env` локальный адрес прокси, например `TELEGRAM_PROXY=http://127.0.0.1:7890`. Без этого параметра бот подключается напрямую.
4. Для включения Dishly Plus добавьте `DEEPSEEK_API_KEY` и согласованную цену `PLUS_MONTHLY_STARS` (целое число Stars). `ADVISOR_DAILY_LIMIT` по умолчанию ограничивает советчика десятью вопросами на пользователя в день. Пока цена пустая, счёт за подписку не выставляется. Если серверу нужен прокси для DeepSeek, укажите `DEEPSEEK_PROXY`. Тексты запросов и настройки, нужные для подбора, отправляются в DeepSeek API; ключ хранится только в `.env`.
5. Запустите `python -m dishly.bot`. Для постоянной работы настройте `systemd` для бота и используемого прокси-клиента.

Перед оплатой пользователь открывает `/terms` и подтверждает условия. Dishly Plus списывает Telegram Stars раз в 30 дней; автопродление можно отключить в `/plus`. Для обращения по оплате есть `/paysupport`. Администратор может найти платежи пользователя командой `/pluspayments USER_ID` и выполнить возврат командой `/refund USER_ID CHARGE_ID`.

Не храните токен, VPN-подписку или конфигурацию прокси в Git. Файлы `.env`, `nevpn*`, журналы `*.log`, `cache.db`, базы `*.sqlite3`, правила Mihomo (`*.mrs`, `rule-sets/`) и копии `*.before-proxy` исключены из репозитория.

### Обновление и обслуживание сервера

Исходные unit-файлы systemd и скрипт резервного копирования находятся в [`deploy/`](deploy/README.md). Конфигурация VPN и токены в Git не хранятся.

Из корня проекта обновите код и перезапустите бота:

```bash
git pull --ff-only
source .venv/bin/activate
python -m pip install -r requirements.txt
sudo systemctl restart dishly.service
sudo systemctl status dishly.service --no-pager
```

Прокси Mihomo отдельно перезапускать не нужно, если его конфигурация не менялась. Просмотр последних сообщений бота и прокси:

```bash
sudo journalctl -u dishly.service -n 60 --no-pager
sudo journalctl -u mihomo.service -n 40 --no-pager
```

SQLite-база ежедневно копируется примерно в 03:00 в `/home/keka/backups/dishly`. Хранятся последние 14 дней; пропущенный при выключении VM запуск таймер выполнит после загрузки. Проверить расписание и вручную запустить копию можно так:

```bash
sudo systemctl list-timers dishly-backup.timer --no-pager
sudo systemctl start dishly-backup.service
sudo systemctl status dishly-backup.service --no-pager
ls -lh /home/keka/backups/dishly
```

Если у `git pull` конфликт из-за локальных изменений, сначала проверьте `git status --short`. Не удаляйте `.env`, `dishly.sqlite3` или конфигурацию Mihomo: там находятся настройки и пользовательские данные.

## Проверка проекта

```powershell
python -m unittest discover -s tests -v
python -m dishly.bot
```

Первую команду можно выполнить без токена. Для запуска приложения токен обязателен. Ошибка настройки сообщает, как создать `.env`; его содержимое не пишется в логи.

## Как устроен поиск

- Поиск локальный и словарный: опечатки, свободные синонимы и сложные формулировки могут не распознаться. Если условия неизвестны базе, бот не может подтвердить их соответствие.
- Запросы ограничены 500 символами. До пяти рецептов показываются на странице; можно перейти вперёд и назад без повторов.
- Неуказанные ингредиенты не считаются имеющимися. Вода, соль и базовые приправы могут быть отмечены необязательными в каталоге.
- `без молочного`, `без глютена`, `без мяса`, `без лука` исключают рецепты по составу и аллергенам. Это фильтр по сохранённым данным, а не гарантия отсутствия следов аллергенов.
- Режим «Фильтры» позволяет совместить продукты, способ приготовления, максимальное время и пожелания. Все выбранные условия применяются строго: продуктовые фильтры требуют наличия каждого отмеченного продукта, способ и пожелания — совпадения всех отметок, время — не превышать лимит.
- В разделе «✨ Ещё» → «🧺 Из моих продуктов» можно перечислить имеющиеся продукты. Dishly ранжирует рецепты по совпадению, показывает использованные продукты, подсказывает, что ещё понадобится, и предлагает подходящие замены из уже имеющегося списка.
- В настройках можно указать аллергены, исключённые продукты и доступную технику. Эти ограничения учитываются при поиске, фильтрах и персональных альтернативах блюда дня; возможные следы аллергенов каталог не описывает.
- В настройках есть подтверждаемый сброс предпочтений с повторным запуском первичной настройки. Он не удаляет избранное и историю.
- Количество ингредиентов масштабируется под выбранное число порций.
- Выдача поиска показывается одним сообщением-каталогом; кнопки переключают страницу или открывают подробную карточку в этом же сообщении.
- Кнопка «Все рецепты» открывает полный каталог с перелистыванием страниц и карточками в одном редактируемом сообщении.
- На приветственном экране отображается брендированный баннер Dishly с капибарой-шефом. Файлы аватарки и баннера лежат в `assets/`; аватарку можно загрузить в профиль бота через BotFather.
- «Блюдо дня» общее для всех пользователей. Кнопка «Другой вариант» показывает дополнительный рецепт только нажавшему пользователю и не меняет общее блюдо; личные варианты за день не повторяются.

## Добавление данных

- Рецепты и демонстрационные записи: `dishly/data/recipes.py`. У каждой записи есть идентификатор, ингредиенты, шаги, время, порции, теги, способ, аллергены и источник.
- Синонимы ингредиентов, теги и группы исключений: `dishly/data/vocabulary.py`.
- Разбор запросов: `dishly/parser.py`; правила фильтрации и ранжирования: `dishly/search.py`.
- Разбор запросов: `dishly/parser.py`; правила ранжирования и исключения: `dishly/search.py`.

При первом запуске данные копируются в SQLite. Чтобы заново импортировать изменённый демонстрационный каталог, остановите бота и удалите локальный `dishly.sqlite3`; это также удалит пользовательские настройки, избранное и историю. Для последующих правок каталога можно редактировать таблицу/добавить миграцию, не удаляя пользовательскую базу.

Данные пользователей разделяются по Telegram user ID. История последних десяти блюд и избранное хранятся локально в SQLite. Логи не содержат полные тексты пользовательских сообщений.
